# M6b 对齐质量实验矩阵

> 生成: 2026-08-17 03:00（5 变体训练完成 + L1 评测完成）

## 配置说明

- 训练：CLIP 512 锚 + InfoNCE，20 epochs，lr=1e-3，init-encoders=token_fusion_seed0.pt，全部 `--init-prototype`，`torch.manual_seed(0)`，cache_size=256
- **batch 变更**：spec 原定 256，16GB 显存满载（15.8GB/16.3GB，97%）且卡死；实测 batch=128 单 step 慢速路径（fwd+bwd 3.3s vs 32 的 0.75s）。改为 **batch=64**（负样本 63/样本，2x baseline，epoch ~110s）。偏差记录见 docs/LESSONS.md。
- 评测：CLIP 512 L1，held-out base 10%（n=918），r@1/5/10 + tr@k + 诊断（mean_rank, same_label_above_pos）

## 训练收敛对比（info_nce 分量）

| 变体 | ep0 info_nce | ep19 info_nce | 说明 |
|---|---|---|---|
| A (batch32) | 3.39 | 3.28 | 基线复现 |
| B (batch64) | 4.02 | 3.83 | 大 batch（单看 loss 反而略差） |
| C (+CE0.5) | 4.01 | 3.83 | 分类辅助 |

## 判定（按 spec 2SE 规则）

- **无显著提升**：r@1 最大提升 0.0022（baseline→A），远低于 2SE≈0.005 阈值；多指标不同向（D 的 r@5 反而更低）。
- 训练 loss 与评测脱节：neg-mine 使 info_nce loss 降 33%（3.8→2.5），但 L1 完全没跟上——**优化了训练目标，没优化评测指标**。

## 结论

**负结果：三种手段（大 batch/分类辅助/负样本挖掘）均未显著提升 CLIP 512 锚下的 L1 检索。**

分析：
1. **评测空间本身无可分性**：n=918 模板文本（TemplateCaptioner 生成）在 CLIP 512 空间几乎不可检索（r@1≈0.004 ≪ 随机 0.037 的一半），**918 个 held-out base 的 caption 高度模板化、语义趋同** → L1 在这个评测集上测不出编码器质量差异。
2. **训练手段被评测天花板压制**：即使 D/E 让 InfoNCE 收敛明显更好（loss 2.5），检索空间不变，r@1 仍是噪声级。手段有效但评测不敏感。
3. **下一步方向**（替代 M6b 训练手段路线）：
   - **换评测**：用 llama2 4096 mean-pool caption 文本侧（M6a spec 定案口径）重测——模板文本在 llama2 空间的区分度可能高于 CLIP。
   - **换数据文本**：M5a 已知 v5 用模板文本，L1 数值反映"模板文本的简单相关性"。等 M5b 的 LLM 后端 caption 落地后重评。
   - 训练手段（neg-mine/CE）保留代码与结论，作为后续换评测后的复测基线。

## 复测（2026-08-17，llama2 4096 mean-pool 文本侧）

> 工具：`scripts/eval_alignment_llm_sweep.py`，LLM 加载一次循环 6 ckpt，结果 `results/m6b_llm4096_sweep.json`

### 配置

- 文本侧：`llama2-7b` mean-pool input embeddings（B, T=64, H=4096 → (B, 4096)），归一化
- 传感器侧：`align.encode_modalities` → `PerceiverProjection(k=8, out_dim=4096)` → mean-pool over M*k → (B, 4096)
- 评测集：与原 CLIP 评测同 held-out base（n=918，同 seed=0 同 fraction=0.1），保证可比

### 结果（双侧对比）

| 变体 | 配置 | LLM r@1 | LLM r@5 | LLM r@10 | LLM mean_rank | CLIP r@1 | Δ r@1 (LLM-CLIP) |
|---|---|---|---|---|---|---|---|
| baseline | 旧 | 0.0076 | 0.0327 | **0.0719** | 202.4 | 0.0022 | +0.0054 |
| A | batch32 复现 | **0.0109** | 0.0338 | 0.0697 | 201.7 | 0.0044 | +0.0065 |
| B | batch64 | 0.0087 | 0.0338 | 0.0708 | 216.4 | 0.0044 | +0.0043 |
| C | +CE0.5 | 0.0044 | 0.0327 | 0.0577 | 251.4 | 0.0044 | 0.0000 |
| D | +neg-mine | 0.0065 | **0.0436** | 0.0773 | 220.5 | 0.0044 | +0.0021 |
| E | 全组合 | 0.0065 | 0.0392 | 0.0697 | 234.9 | 0.0033 | +0.0032 |

2SE 参考：n=918，p≈0.01 → 2SE≈0.0066；p≈0.04 → 2SE≈0.0182。

### 判定

1. **llama2 4096 评测空间更敏感**：
   - baseline r@1 提升 3.5x（0.0022 → 0.0076）；r@5/r@10 各 ~2x
   - 变体 r@1 极差扩大（CLIP 0.0033-0.0044 ≈ 1.3x → LLM 0.0044-0.0109 ≈ 2.5x）
   - **确认原报告"评测天花板"部分成立**：CLIP 512 不可分；llama2 4096 仍弱但能区分变体
2. **变体间仍无显著差异**（按 2SE 严格判定）：
   - **A vs baseline r@1 Δ=0.0033**，恰好 1SE（0.0066/2），未到 2SE → **不显著**
   - D r@5=0.0436 Δ vs baseline 0.0109 ≈ 0.6SE → 不显著
   - C 双侧都最差（LLM 0.0044，CLIP 0.0044 持平 baseline）→ CE 损 r@1 跨评测空间稳定
3. **训练手段路线整体未救活**：
   - 即使换评测空间，InfoNCE loss 收敛（D/E 2.5）也没转化为跨模态检索的统计显著提升
   - 模板 caption + 27 类细粒度动作语义在 llama2 4096 仍不可细粒度检索（r@1 max 0.0109 ≪ 随机 1/27≈0.037）
4. **跨评测空间一致性**：
   - C（CE）始终最差 → 分类辅助过拟合 27-way，反而拖累文本对齐（clip/llama2 同步）
   - baseline 与 A/B/E 同档 → 复现实验稳定

### 结论（更新）

**M6b 训练手段路线在 CLIP/llama2 双评测空间下均未显著提升 L1**。
原"评测天花板"论断部分成立——llama2 4096 替换成功缓解，但模板 caption 的细粒度语义瓶颈仍在。
**剩余路径**（优先级）：
1. **换评测目标**：动作-动作相似度（verb-to-verb probe）或类内紧致度（class-conditional retrieval）——绕开"整句 caption 模板化"陷阱
2. **换数据文本**：M5b 的 LLM 后端 caption 落地后重测，模板→自然语言后 L1 上限应明显抬升
3. **换目标函数**：27 类对齐目标（CE only）替代/补充 InfoNCE——C 的负结果反过来说明分类头对细粒度对齐"过强"但"对文本不对齐"
