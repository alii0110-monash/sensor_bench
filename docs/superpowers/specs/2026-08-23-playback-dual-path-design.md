# 播放器双模式重设计（方案 A）

日期：2026-08-23
状态：[提议]

## 背景与动机

当前 review 页播放器用**服务器驱动帧推进**（`time.sleep + st.rerun`），有两个固有问题：

1. **帧切换卡**：每帧触发 Streamlit 整页重跑，全模态重建 figure，3D（WebGL）尤其慢，帧率上不去。
2. **3D 视角重置**：播放时逐帧 redraw，plotly gl3d scene 重建导致用户旋转的相机被重置回默认视角。

历史教训（`2e2401a` → `0ea6c8e`）：纯 plotly 客户端动画"拖动滑块时图表消失/不动"，被回退。

## 目标

用户核心诉求（已确认）：
- **帧切换流畅为主**（播放时不需交互）。
- **记录起始旋转视角，播放中锁定不变，中途不再调整**。

## 方案 A：双路径渲染

**播放态（客户端动画）** 与 **暂停态（静态帧）** 独立两张图，互不覆盖。

- **播放态**：`render_animated()` 构建一个含全部帧的 plotly 图（frames + 内置播放/暂停/滑块），**纯浏览器端推进，零服务器 rerun** → 帧流畅。
- **暂停态**：单帧静态图，3D 可旋转。拖滑块看单帧。

### 交互（用户拍板：去掉总开关）

每个模态**始终**渲染为一个动画图（自带播放/暂停/滑块），**直接点任意模态自己的播放按钮即可**，不再需要先点顶部总开关。无顶部全局播放切换。动画图按样本缓存（切换样本构建一次，rerun 复用）。

### 播放机制决策（真机验证后修正）

初版用 `redraw:false`（意图保留用户 3D 相机）。真机发现 `redraw:false` 只更新数据引用、不重绘画布，导致 **depth 热图、lidar/mmwave WebGL 3D 不刷新**（仅 2D 线图 wifi/rgb 能动）。

**最终决策（用户确认）**：播放按钮改 `redraw:true` —— 所有模态（线图/热图/3D）重建画布、全部能动。代价：redraw 每次重建 gl3d scene，**播放时 3D 相机重置回默认**；暂停态静态帧图仍保留用户旋转视角供查看。

### 复杂度边界（诚实声明）

- 3D 逐帧动画依赖 WebGL 重绘，headless（无 GPU）无法 100% 确认，需真实浏览器验收。已在真机确认：`redraw:true` 下所有模态（含 depth 热图、lidar/mmwave 3D）都能播放动画。

## 数据体积控制

- depth 动画降采样（spatial dims /4 或 /8）
- lidar 每帧限点（600）
- 每样本动画图缓存（切换样本构建一次，rerun 复用）

## 组件化可选增强（暂缓）

"自动捕获相机"自定义组件（`declare_component` 回传相机）已验证 iframe 可读写父页面相机，但 Streamlit 双向回传协议（`streamlit-component-lib`）需 npm 前端构建，复杂度高。**当前不做组件**：播放用 `redraw:true`（全模态能动，3D 播放时回默认视角），暂停态静态帧图可旋转供查看。若需"播放时 3D 保留视角"，再评估手填 eye 坐标 + 锁定按钮。

## 测试

- `render_animated` 单测（帧数、depth 降采样、lid 限点、slider/updatemenu 存在）
- 现有播放器回归（AppTest 冒烟）
- 浏览器手动验收：播放流畅、拖动滑块不消失、所有模态（含 3D）播放能动
